# 데이터 계약 — 실행 전에 요청을 예측한다

수업용 합성 요청 100건입니다. 실서비스 성능을 입증하는 데이터가 아닙니다.
원본 생성 seed=23. 분할은 Day5의 두 차례 층화 분할(seed=42) 결과를 재사용합니다.
새로 분할하지 않고 `split_manifest.csv`와 `split_order.csv`를 읽습니다.
manifest는 소속만 기록하고 position은 기록하지 않기 때문에 별도 순서표가 필요합니다.

| 열 | 종류·단위 | 사용 |
|---|---|---|
| request_id | 요청 ID, R001~R100 | 정렬·분할 확인만, 입력 제외 |
| input_chars | 글자 수 | 수치형 입력, 결측은 train 중앙값 |
| allowed_tools | 허용 도구 수 | 수치형 입력, 결측은 train 중앙값 |
| task_type | qa/research/summary | 범주 입력, 최빈값·원핫 |
| priority | low/normal/high | 범주 입력, 최빈값·원핫 |
| elapsed_ms | 실제 실행시간, ms | 회귀 y. 분류 X에 넣으면 실행 후 정보 누수 |
| failed | 0=성공,1=실패 | 분류 y. 회귀 X에도 사용하지 않음 |
| status | ok/error | 실행 후 값, 모든 X에서 제외 |
| retry_count | 재시도 수 | 실행 후 값, 모든 X에서 제외 |

입력 열은 정확히 4개, 순서는 input_chars·allowed_tools·task_type·priority입니다.
train 60건=성공42/실패18, valid20건=성공14/실패6. test20건은 ID만 보관합니다.
수치형 중앙값은 train에서 [1315,3], 범주형 최빈값은 [research,low]가 됩니다.
원핫의 범주별 실제 순서는 `get_feature_names_out()`으로 확인하며 하드코딩하지 않습니다.

`checkpoints/train.csv`, `valid.csv`는 원본의 해당 행·순서를 담은 **미전처리** 파일입니다.
결측값을 미리 전체 평균으로 채우지 않았습니다. 별도 통계 학습 자료가 아닙니다.
이 실습07에서는 앞 실습의 `knn_search_reference.csv`나 `knn_search_from_ex06.csv`를 사용하지 않습니다.
KNN 이웃 수는 `model_config.py`의 분류 3개·회귀 15개로 사전에 고정합니다.

새 입력 N001은 기존 범주, N002는 수치 결측과 translation·urgent라는 미지 범주를 포함합니다.
새 범주는 오류가 아니라 원핫 해당 블록 0으로 처리합니다. 필수 열 누락·금지 열 추가는 명확한 오류입니다.
원본 자료의 입력 전체 결측 열 정책은 train 사전 검사에서 중단입니다. 새 입력의 결측은 학습 규칙으로 처리합니다.
