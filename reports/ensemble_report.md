# 앙상블 모델 실험 보고서

작성일: 2026-10-27. 이 문서는 AI 지원으로 실제 실행 결과를 읽어 작성했다. 사용자가 직접 서술하거나 이해도를 확인한 기록으로 간주하지 않는다. 수치는 이 프로젝트의 `outputs/`에서 가져왔고, 표에는 읽기 쉽게 반올림했다. 원본 CSV의 정밀도는 유지했다.

이번 실행의 사전 규칙에 따른 선택은 **분류 XGB, 회귀 KNN15**다. 분류의 valid 최고 모델은 KNN3이고, 회귀의 valid RMSE 최저 모델은 Linear였다. 선택 규칙과 별도 진단 결과가 다른 사례이며, 이 결과만으로 어느 모델의 실서비스 우위를 입증한 것은 아니다.

## 1. 무엇을 예측하는가

요청을 실행하기 전에 실패 여부와 실행 시간을 예측하는 수업용 실험이다. 분류 정답은 `failed`의 0=성공, 1=실패이며, 회귀 정답은 `elapsed_ms`의 실제 실행 시간(ms)이다. 같은 요청에 대해 서로 다른 정답을 예측하므로 분류와 회귀 모델을 따로 학습한다.

[데이터 사전](../data/데이터_사전.md)에 따르면 자료는 생성 seed 23의 합성 요청 100건이다. 실서비스 관측 자료가 아니므로 운영 비용 절감이나 장애 감소를 입증하는 데 사용할 수 없다.

| 입력 열 | 의미 | 실행 전에 사용할 수 있는 정보와 처리 방법 |
|---|---|---|
| `input_chars` | 입력 글자 수 | 수치 입력. 결측은 해당 학습 부분의 중앙값으로 채운다. |
| `allowed_tools` | 허용된 도구 수 | 수치 입력. 같은 방식으로 결측을 채운다. |
| `task_type` | qa/research/summary 작업 종류 | 결측을 최빈값으로 채운 뒤 원핫 인코딩한다. |
| `priority` | low/normal/high 우선순위 | 결측을 최빈값으로 채운 뒤 원핫 인코딩한다. |

`request_id`는 행을 추적하고 정렬하는 식별자로만 사용한다. `failed`와 `elapsed_ms`는 정답이므로 입력에서 제외한다. 특히 실제 실행 시간, `status`, `retry_count`는 요청을 실행한 뒤 알 수 있는 정보다. 이를 입력에 넣으면 실행 전에 모를 정보를 미리 알려 주는 데이터 누수가 생긴다. 회귀 모델에도 실행 후 실패 여부를 입력으로 주지 않는다.

입력은 항상 위 순서의 4열이다. 학습 뒤의 변환 결과는 숫자 2열과 범주별 원핫 6열을 합친 8열이다. 원핫 열 순서는 코드가 `get_feature_names_out()`으로 읽으며 문서의 표를 이용해 하드코딩하지 않는다.

## 2. 자료를 나누고 전처리를 학습하는 순서

새로 무작위 분할하지 않고 `split_manifest.csv`의 소속과 `split_order.csv`의 행 순서를 재사용했다.

| 구분 | 행 수 | 역할 |
|---|---:|---|
| train | 60 | 후보의 교차검증과 최종 학습. 성공 42건·실패 18건. |
| valid | 20 | 전체 train으로 학습한 각 후보의 별도 진단. 성공 14건·실패 6건. |
| test | 20 | 보관. 로더는 test의 입력·정답을 모델 평가용으로 반환하지 않는다. |

원본 CSV에는 전체 요청이 들어 있지만 `DevData`에는 `X_test`나 `y_test`가 없다. 따라서 test ID를 이용한 분할 무결성 확인과 test의 예측·성능 평가는 구분해야 한다. 이번 실행의 `test_evaluated`는 `false`다.

교차검증은 train 60건 안에서 5회 진행한다. 각 회차는 48건을 학습하고 12건을 평가한다. 분류에는 클래스 비율을 가능한 한 유지하는 `StratifiedKFold`, 회귀에는 `KFold`를 사용했으며 모두 `shuffle=True`, `random_state=42`다. 같은 과제의 모든 후보는 같은 fold를 사용한다.

전처리와 모델을 하나의 Pipeline으로 복제해서 각 fold 안에서 학습한다. 예를 들어 첫 fold의 중앙값은 그 fold의 48건에서만 계산한다. 60건 전체의 중앙값으로 미리 채운 뒤 나누면 평가 12건의 정보가 학습에 섞인다. [cv_scores.csv](../outputs/cv_scores.csv)의 분류 30행·회귀 30행 모두 `median_audit_passed=True`이며, 학습된 중앙값을 각 fold 입력의 중앙값과 대조했다. fold별 실제 소속은 [fold_manifest.csv](../outputs/fold_manifest.csv)에 남겼다.

CV가 끝난 뒤 각 후보를 전체 train 60건으로 별도 학습하고 valid를 예측했다. 전처리는 train에서 배운 규칙을 재사용한다. 미지 범주는 해당 범주 블록을 0으로 처리하며, 새 자료를 예측한다고 평균·중앙값·범주를 다시 배우지 않는다.

## 3. 어떤 후보를 왜 비교했는가

복잡한 모델만 비교하면 단순 기준선보다 실제로 나은지 알기 어렵다. 그래서 기준선, 선형 관계, 가까운 사례, 단일 트리, 두 가지 앙상블을 함께 비교했다. 후보를 포함한 이유와 실행 결과로 후보를 선택하는 이유는 구분한다.

| 후보 | 비교에 포함한 이유 | 주요 고정 설정 |
|---|---|---|
| Dummy | 입력 관계를 배우지 않는 기준선보다 나은지 확인 | 분류는 최빈 클래스, 회귀는 train 정답 평균 |
| Logistic / Linear | 비교적 단순한 선형 관계의 기준 | Logistic `C=1`, `max_iter=1000`; 회귀는 LinearRegression |
| KNN3 / KNN15 | 비슷한 입력의 학습 사례를 참고하는 접근 비교 | 분류 이웃 3건, 회귀 이웃 15건 |
| Tree | 조건에 따른 비선형 분기 비교 | 최대 깊이 3, 최소 잎 표본 3건, seed 42 |
| Forest | 여러 트리를 결합한 결과 비교 | 트리 100개, 깊이 4, 최소 잎 2건; 특성 표본은 분류 sqrt·회귀 1.0 |
| XGB | 이전 예측을 순차적으로 보정하는 앙상블 비교 | 80회차, 깊이 2, 학습률 0.05, 행 표본 0.8, 열 표본 1.0, L2 규제 1.0 |

Dummy·Logistic/Linear·KNN에는 숫자 두 열의 표준화를 적용했다. 특히 거리로 이웃을 찾는 KNN에서는 글자 수의 큰 단위가 도구 수를 압도하지 않도록 한다. Dummy의 표준화는 프로젝트의 공통 계약에 따른 것이며, Dummy 자체는 입력의 거리를 사용하지 않는다. Tree·Forest·XGB는 숫자 열을 표준화하지 않았다. 범주 원핫 열에는 StandardScaler를 적용하지 않았다.

XGB의 분류 목적함수는 `binary:logistic`, 회귀 목적함수는 `reg:squarederror`다. `eval_metric` 설정만으로 별도 valid 평가나 조기 종료가 실행되는 것은 아니다. 이번에는 80회차를 고정했고 valid를 조기 종료에 사용하지 않았다.

## 4. 선택 규칙과 지표를 먼저 고정한다

분류는 **train 내부 5-fold F1 평균 최대**, 회귀는 **train 내부 5-fold RMSE 평균 최소**로 선택한다. 반올림하기 전 값이 정확히 동점일 때만 선언 순서를 적용한다. 분류 순서는 Dummy→Logistic→KNN3→Tree→Forest→XGB, 회귀는 Dummy→Linear→KNN15→Tree→Forest→XGB다. valid 점수나 모델 이름으로 재정렬하여 선택하지 않는다.

F1은 실패(1)에 대한 정밀도와 재현율의 조화평균이다. 성공이 더 많은 자료에서 정확도만 보면 모두 성공으로 예측하는 모델을 좋게 보게 될 수 있다. F1은 이를 살피는 한 지표지만, 잘못된 경고와 놓친 실패의 실제 비용을 직접 반영하지는 않는다.

RMSE는 제곱 오차 평균의 제곱근으로 큰 오차에 더 민감하다. 이 과제는 RMSE를 선택 지표로 정했고, 해석을 돕기 위해 평균 절대 오차인 MAE와 R²도 기록한다. CV의 회귀 scorer가 반환하는 음수 RMSE는 코드에서 양수 ms로 복원했다.

표준편차는 다섯 fold 점수의 흩어짐을 `ddof=0`으로 계산한 값이다. 평균 옆에 적힌 표준편차는 신뢰구간이나 모델 우위의 통계 검정 결과가 아니다. fold 간 학습 자료도 겹치므로 서로 완전히 독립적인 다섯 실험으로 해석하지 않는다.

## 5. 분류 6후보의 실제 결과

출처: [classification_comparison.csv](../outputs/classification_comparison.csv). F1은 높을수록 좋다. `train F1`은 전체 60건 학습 모델이 이미 배운 자료에서 얻은 값이다.

| 후보 | CV 평균 F1 | CV 표준편차 | train F1 | valid F1 | FP | FN |
|---|---:|---:|---:|---:|---:|---:|
| Dummy | 0.0000 | 0.0000 | 0.0000 | 0.0000 | 0 | 6 |
| Logistic | 0.5219 | 0.2092 | 0.6207 | 0.3333 | 4 | 4 |
| KNN3 | 0.3356 | 0.1764 | 0.5714 | **0.5455** | 2 | 3 |
| Tree | 0.5424 | 0.1236 | 0.7097 | 0.3333 | 4 | 4 |
| Forest | 0.2800 | 0.2544 | 0.8000 | 0.2222 | 2 | 5 |
| **XGB: CV 선택** | **0.5467** | 0.1046 | 0.7742 | 0.2000 | 3 | 5 |

XGB의 fold F1은 `[0.4000, 0.6667, 0.6667, 0.5000, 0.5000]`이고, 평균 원값은 `0.5466666667`이다. Tree의 `0.5424242424`보다 약 `0.00424` 높아 규칙대로 XGB를 선택했다. 차이가 작고 fold마다 점수가 달라지므로 XGB가 확실히 우월하다고 단정하지 않는다.

valid에서는 KNN3가 가장 높다. CV는 train 안에서 학습 48건·평가 12건을 바꾸며 얻은 평균이고, valid는 train 전체 60건으로 학습한 모델의 다른 20건에 대한 결과다. 학습량과 평가 표본이 모두 달라 순위가 바뀔 수 있다. valid 최고 모델로 지금 선택을 바꾸면 valid까지 모델 선택에 사용한 새로운 절차가 되므로, 이번 기록에서는 사전 규칙의 선택과 진단 결과를 함께 보고한다.

Dummy는 valid 정확도 0.70이지만 실패 6건을 전부 놓쳐 F1은 0이다. Forest 역시 train F1 0.80이 valid F1 0.2222로 이어지지 않았다. 학습 점수만으로 후보를 고르면 안 되는 실제 사례다.

## 6. 잘못된 분류를 요청 ID로 확인한다

출처: [validation_predictions.csv](../outputs/validation_predictions.csv)의 `task=classification`, `model=XGB` 행.

| 구분 | 실제 → 예측 | 요청 ID |
|---|---|---|
| FP: 잘못된 실패 경고 3건 | 성공 0 → 실패 1 | R087, R019, R086 |
| FN: 놓친 실패 5건 | 실패 1 → 성공 0 | R044, R050, R035, R034, R001 |
| TP: 맞힌 실패 1건 | 실패 1 → 실패 1 | R033 |
| TN: 맞힌 성공 11건 | 성공 0 → 성공 0 | 나머지 성공 요청 11건 |

이 모델은 실패라고 예측한 4건 중 1건을 맞혀 정밀도 0.25이고, 실제 실패 6건 중 1건을 찾아 재현율 약 0.1667이다. 따라서 F1은 `2×1/(2×1+3+5)=0.2`다. 이는 정확도 20%라는 뜻이 아니다. XGB의 valid 정확도는 0.60이다.

R001의 입력은 글자 수 1549, 허용 도구 수 4, 작업 종류 summary, 우선순위 normal이다. 실제로는 실패했지만 XGB의 실패 확률 출력은 `0.194725`이고 최종 분류는 0이어서 FN에 포함된다. 이 확률은 모델의 출력이며 실제 환경에서 보정된 발생 확률임을 검증한 값은 아니다. R087은 실제 성공인데 실패 확률 `0.660899`, 예측 1로 FP가 되었다.

FP는 불필요한 검토나 경고를 늘릴 수 있고, FN은 실패에 대한 사전 대응 기회를 놓칠 수 있다. 다만 **어느 오류가 더 비싼지는 확인되지 않았다.** 특히 “실패 놓침의 비용이 더 높다”는 것은 추가로 확인할 업무 가정이다. 이번 실험으로 비용 절감 효과나 운영 배포 적합성을 주장하지 않는다.

## 7. 회귀 6후보와 큰 오차의 해석

출처: [regression_comparison.csv](../outputs/regression_comparison.csv). RMSE·MAE의 단위는 ms이며 낮을수록 좋다.

| 후보 | CV RMSE 평균 | CV 표준편차 | train RMSE | valid MAE | valid RMSE | valid R² |
|---|---:|---:|---:|---:|---:|---:|
| Dummy | 606.184 | 100.844 | 594.422 | 541.260 | 658.745 | -0.1617 |
| Linear | 639.832 | 57.721 | 546.648 | 551.797 | **639.996** | -0.0966 |
| **KNN15: CV 선택** | **598.850** | 91.213 | 561.846 | **530.063** | 641.788 | -0.1027 |
| Tree | 599.635 | 96.116 | 475.196 | 632.028 | 719.001 | -0.3840 |
| Forest | 624.011 | 96.974 | 425.872 | 600.337 | 690.368 | -0.2760 |
| XGB | 650.892 | 92.295 | 430.962 | 610.197 | 700.410 | -0.3134 |

KNN15의 CV RMSE가 가장 낮아 선택했다. Tree보다 약 0.785ms, Dummy보다 약 7.334ms 낮은 정도이므로 차이의 크기와 fold 변동을 함께 본다. valid RMSE 최저는 Linear이지만 선택 지표인 train 내부 CV 순위는 다르다. MAE 최저는 KNN15이므로 “valid에서 가장 좋다”는 표현에도 어떤 지표인지 명시해야 한다.

KNN15의 valid MAE 530.063ms는 20건에서 절대 시간 오차가 평균 약 0.530초였다는 뜻이다. RMSE 641.788ms는 더 큰 오차의 영향을 반영한다. R²가 음수라는 것은 이 valid 자료의 정답 평균을 항상 예측하는 기준보다 제곱 오차가 컸다는 뜻이다. 여기서 비교하는 valid 평균 기준과 **train 평균을 예측하는 Dummy 모델**은 서로 다르다. 모든 후보의 valid R²가 음수여서 현재 입력과 자료로 실행 시간을 충분히 설명한다고 보기 어렵다.

| 요청 | KNN15 실제 시간 | KNN15 예측 시간 | 잔차: 실제−예측 | 해석 |
|---|---:|---:|---:|---|
| R034 | 2608.000 | 1327.267 | +1280.733 | valid에서 이 모델의 절대 오차가 가장 큰 사례. 시간을 약 1.281초 짧게 예측했다. |
| R042 | 149.000 | 1335.867 | -1186.867 | 시간을 약 1.187초 길게 예측했다. |
| R001 | 1994.000 | 1252.733 | +741.267 | 실제보다 약 0.741초 짧게 예측했다. 분류 오류와 별개로 회귀 오차를 기록한다. |

R034와 R042는 모두 summary/high이면서 실제 시간은 크게 다르다. 이 사례는 현재 네 입력만으로 구분하기 어려운 변동이 있을 수 있음을 보여 준다. 다만 두 사례만으로 원인을 확정할 수는 없다. KNN15가 이웃 15건의 정답을 평균하여 극단값을 완만하게 예측하는 특성과 함께 추가로 살펴볼 지점이다.

## 8. 중요도는 어떤 모델·자료에서 계산했는가

[feature_importance.csv](../outputs/feature_importance.csv)는 **train 60건으로 학습한 분류 Forest**를 설명한다. CV로 선택한 분류 XGB의 설명 자료가 아니고, 회귀 KNN15의 설명도 아니다.

MDI는 학습된 트리의 불순도 감소를 변환된 8열에 배분한 값이다. 상위 두 열은 `num__input_chars=0.564256`, `num__allowed_tools=0.166960`이었다. 이는 해당 Forest가 학습 자료를 나눌 때의 상대적 기여이며, 실패 원인이나 신규 자료의 성능을 직접 측정한 수치가 아니다. 고유값이 많은 특성에 유리할 수 있고, 원핫 범주는 여러 열로 나뉘어 있다는 점도 고려해야 한다.

순열 중요도는 같은 Forest를 고정하고 valid의 **원본 4열**을 하나씩 섞어 F1이 얼마나 떨어지는지 측정했다. 각 열을 10회 섞었고 `random_state=42`를 사용했다. 원본 범주 열을 섞은 뒤 Pipeline이 변환하므로 여러 원핫 열을 묶은 입력 단위로 진단한다.

| 원본 입력 | 평균 F1 감소 | 반복 표준편차 |
|---|---:|---:|
| input_chars | 0.067778 | 0.136101 |
| allowed_tools | 0.054192 | 0.118549 |
| task_type | 0.173651 | 0.099016 |
| priority | -0.020556 | 0.180124 |

순열에서는 task_type의 평균 감소가 가장 크다. MDI와는 계산 자료·단위·방법이 달라 수치나 순위가 일치할 필요가 없다. priority의 음수 평균은 이 작은 valid에서 섞은 뒤 F1이 평균적으로 조금 올랐다는 뜻이다. 반복 변동도 크므로 priority가 해롭다고 확정하거나 자동으로 삭제하지 않는다. 순열 반복 표준편차 역시 신뢰구간이 아니다.

## 9. TreeGrid는 기본 비교와 분리한다

별도 실험은 Tree의 깊이 `[2, 4]`와 최소 잎 표본 수 `[1, 3]`를 조합한 4조건이다. 각 조건을 같은 train 내부 5-fold F1으로 평가하고, 최적 조건을 train 60건으로 다시 학습했다. valid와 보관 test는 탐색에 사용하지 않았다.

출처: [separate_tree_grid.csv](../outputs/separate_tree_grid.csv), [separate_tree_grid.json](../outputs/separate_tree_grid.json).

| 깊이 | 최소 잎 표본 수 | CV 평균 F1 | CV 표준편차 | 순위 |
|---:|---:|---:|---:|---:|
| 2 | 1 | 0.493333 | 0.097525 | 3 |
| 2 | 3 | 0.493333 | 0.097525 | 3 |
| 4 | 1 | **0.718730** | 0.238705 | 1 |
| 4 | 3 | 0.672063 | 0.231649 | 2 |

선택된 탐색 조건은 깊이 4·최소 잎 1이다. 여러 조건 중 높은 점수를 고른 만큼 선택 편향이 포함되어 있고, 평가를 위한 별도의 바깥 CV는 수행하지 않았다. 이 점수를 독립 최종 성능으로 보거나 기본 XGB보다 확실히 좋다고 결론 내리지 않는다. `basic_table_replaced=false`이며, 기본 비교표와 선택 모델을 이 결과로 바꾸지 않았다. 조기 종료 실험은 하지 않았다.

## 10. 이번 결과의 한계와 다음 실험

검증 실패가 6건뿐이어서 한두 건의 예측 변화가 F1을 크게 바꾼다. train도 60건인 합성 자료다. 또한 valid는 이전 실습부터 반복해서 진단한 자료이며, 여러 후보 중 CV 최고를 선택한 점수에도 선택 편향이 있다. 이번 수치를 독립적인 최종 성능이나 실서비스 성능으로 설명하지 않는다.

다음 실험은 보관 test를 예측하지 않는 상태에서 아래 순서로 준비할 수 있다. 아직 수행한 실험으로 기록하지 않는다.

1. **오류 비용부터 확인한다.** FP와 FN이 어떤 조치를 유발하고 비용이 얼마나 다른지 확인한다. FN 비용이 크다는 업무 가정이 확인되면 재현율·경고량·Fβ 등 목표와 임계값 결정 규칙을 먼저 정한다.
2. **train 안에서만 안정성을 더 살핀다.** 후보와 반복 횟수·seed를 미리 정한 반복 CV로 작은 순위 차이를 확인한다. 파라미터나 임계값까지 고른다면 안쪽에서 선택하고 바깥에서 평가하는 중첩 CV를 고려한다.
3. **오류 사례와 입력의 한계를 조사한다.** R001의 실패와 R034·R042의 시간 차이를 설명할 실행 전 정보가 있는지 확인한다. 실행 후 status·retry_count를 추가하는 방식으로 누수를 만들지 않는다.
4. **최종 절차를 고정한 뒤 별도 평가를 계획한다.** 합성 자료와 다른 독립 자료가 필요하며, 현재 보관 test는 모델·지표·임계값을 고정한 최종 평가용으로 남긴다. 이번 작업에서는 test 성능을 계산하지 않았다.
